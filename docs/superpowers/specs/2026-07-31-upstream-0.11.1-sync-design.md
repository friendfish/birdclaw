# Upstream 0.11.1 Sync Design

**Status:** Approved on 2026-07-31

## Context

The fork's `main` and `upstream/main` share commit `3c173a7`. Since that
point, the fork has 116 unique commits and upstream has four unique commits:

- `ac2e269` refreshes compatible lockfile resolutions.
- `8ead95b` completes the dependency refresh, pins `@hono/node-server` to
  2.0.12, and relaxes four demonstrated test timeouts.
- `e7605cf` publishes version 0.11.1.
- `ec65195` opens the 0.11.2 development section.

The upstream-only range contains no CLI or page production-code changes. A
virtual three-way merge reports one content conflict, in `CHANGELOG.md`.

## Goals

- Preserve upstream ancestry so future syncs recognize these commits.
- Incorporate the 0.11.1 dependency, security, test, and release maintenance.
- Preserve every fork-specific feature and fix added after the common base.
- Keep upstream 0.11.1 release history distinct from fork-only 0.11.2 work.
- Deliver the sync through an isolated branch and pull request.

## Non-Goals

- Do not add or change CLI capabilities.
- Do not add or change page behavior.
- Do not reuse or rewrite the historical `sync/upstream-main` branch.
- Do not refactor production code while resolving the sync.

## Merge Strategy

Create `codex/sync-upstream-0.11.1` from the current `main` in a project-local
ignored worktree. Fetch both remotes, confirm the expected upstream head, and
perform a non-fast-forward merge of `upstream/main`. This follows the ancestry-
preserving pattern used by PR #23 and makes later upstream merges predictable.

The merge accepts the upstream versions of `package.json`, `pnpm-lock.yaml`,
`pnpm-workspace.yaml`, and the four timeout-only test changes. The only manual
resolution is `CHANGELOG.md`.

## Changelog Resolution

The merged changelog must have this release structure:

1. `0.11.2 - Unreleased` contains only fork work added after upstream 0.11.1:
   editable prompt templates and playgrounds, prompt-order changes, live data
   source controls, Bird/xurl transport semantics, override documentation, and
   the fork's DM/mention/config fixes.
2. `0.11.1 - 2026-07-27` preserves upstream's highlights, tombstone and edit
   history entries, merge-by-default import behavior, dependency refresh, and
   Hono maintenance note.
3. Older release sections remain byte-for-byte unchanged unless Git's merge
   result already contains an upstream correction.

`package.json` follows upstream and reports version `0.11.1`; the top changelog
section remains `0.11.2 - Unreleased` for ongoing fork development.

## Expected Change Surface

In addition to these design and plan documents, the sync may change only:

- `CHANGELOG.md`
- `package.json`
- `pnpm-lock.yaml`
- `pnpm-workspace.yaml`
- `src/lib/tweet-repository.test.ts`
- `src/routes/links.test.tsx`
- `src/routes/profiles.$handle.test.tsx`
- `src/routes/today.test.tsx`

Any production file change is a stop condition requiring renewed analysis.

## Validation

Validation proceeds from narrow to broad:

1. Install exactly the merged lockfile with `pnpm install --frozen-lockfile`.
2. Run the four tests touched upstream.
3. Run `pnpm run check`.
4. Run the complete `pnpm test` suite.
5. Run `pnpm run build` and `pnpm run pack:smoke`.
6. Run `pnpm audit --prod --audit-level=low`.
7. Verify the merge parents, expected file set, clean status, and absence of
   whitespace errors.

The local machine currently provides Node 26.4.0 while the repository declares
`>=26.5.0 <27`. This warning is recorded in the result. It is not silently
treated as a matching runtime, even if all verification commands pass.

## Failure Handling

- If `upstream/main` moves beyond `ec65195`, stop and re-audit the new commits.
- If any file other than `CHANGELOG.md` conflicts, stop and reassess scope.
- If dependency installation changes the lockfile, stop; the frozen lockfile is
  the source of truth.
- If a test or build fails, distinguish environment restrictions from code
  failures, rerunning sandbox-blocked localhost tests only with approval.
- Before the merge commit exists, `git merge --abort` restores the isolated
  branch. The primary `main` worktree remains untouched throughout.

## Acceptance Criteria

- The branch contains upstream head `ec65195` as a merge parent.
- The expected dependency and Hono override changes are present.
- The changelog cleanly separates upstream 0.11.1 from fork 0.11.2 work.
- No CLI or page production source changes are introduced by the sync.
- All available validation gates pass, with environment deviations disclosed.
