建议微调
“历史归档支持部分 source 失败后继续”不是独有差异，当前态编排同样继续后续 source。真正差异是最终状态：当前态部分成功为 degraded，归档任一生成失败即为 failed。因此 failurePolicy 仍值得抽象，但理由应写成“状态归类不同”。
“内部全 Effect”过于绝对。更合适的约定是：禁止在活跃 Effect 内启动嵌套 runtime；Promise/Effect 只在明确适配边界转换，并要求长任务传播取消信号。
Node 信息属于审查环境，不是源码缺陷。仓库已经通过 [.node-version (line 1)](/Users/friendfish/Repo/birdclaw/.node-version:1) 固定 26.5.0；当前终端实际是 v24.18.0，而报告记录的是 26.4.0，说明运行环境没有稳定遵循版本文件。行动项应改成“让 CI/开发工具强制采用 .node-version”，而不是泛化为“升级 Node”。
修正后，行动顺序建议调整为：归档 schema 与错误分类 → launchd 串行化/取消设计 → 无行为拆分 → 补真正缺失的故障测试 → 共享 batch runner。这样这份报告就可以作为后续重构的正式基线。
